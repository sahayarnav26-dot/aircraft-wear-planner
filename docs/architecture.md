# Architecture

Every landing triggers one pass from sensor history to a ranked parts option, and a person makes the final
call. Nothing is reserved, moved or ordered until the planner approves; the system only recommends.

![System architecture](images/architecture.png)

The diagram is generated by `docs/diagrams/make_architecture.py` (`architecture_slide.png` is the same picture
without the title, for a slide that has its own heading).

## Components

| Layer | What it does | Built with | Code |
| --- | --- | --- | --- |
| Data | NASA C-MAPSS FD001 sensor histories; synthetic network, stock, suppliers and fleet; cited emission factors | CSV files | `data/` |
| Wear estimation | LSTM on the last 30 cycles of 14 sensors (5-fold ensemble); Monte Carlo dropout band calibrated by conformal prediction; top 3 sensors by occlusion. A LightGBM baseline is kept for comparison, and a fixed rule promotes the better model | PyTorch, LightGBM, scikit-learn | `ml/` |
| Model-to-planner contract | One row per engine per cycle: estimate, band, true RUL (replay engines only), top sensors, model version | CSV | `outputs/predictions.csv` |
| Planning engine | Urgency tier and need-by time from the lower edge; builds and ranks reserve, transfer, standard and expedited options | Python | `core/planning.py` |
| Fleet optimizer | Allocates scarce spares across engines in one model so no spare is promised twice | PuLP with the HiGHS solver | `core/optimizer.py` |
| Fleet simulation | Aircraft fly fixed rotations; each landing adds a cycle, re-runs the planner and raises alerts; end of life grounds the aircraft | Python | `core/fleet_sim.py` |
| Policy comparison | Replays all engines under reactive and predictive policies with shared stock | Python | `core/policy_sim.py` |
| Dashboard | Five views: fleet, engine, landing, parts plan, impact; approve, override and decision log | Streamlit, Plotly | `app/streamlit_app.py` |
| API (optional) | The same core functions over REST | FastAPI | `api/main.py` |

## Workflow after each landing

1. A flight cycle completes and the engine's new readings arrive.
2. The model returns the RUL estimate, its 80% band and the top sensors.
3. The planner sets the tier from the lower edge of the band: Review before next departure (≤ 10 cycles),
   Plan maintenance (≤ 40) or Monitor.
4. It computes the need-by time: landing time + (lower edge − 5-cycle safety buffer) ÷ the aircraft's flights per day.
5. It lists every way to get the part to the base and marks each on time or late.
6. On-time options are scored by normalised cost and freight CO2e; the slider sets the weight. If none is on time,
   the fastest option is shown and escalated with the shortfall in hours. In Monitor, an "order soon" flag appears
   when the best option must be ordered within 7 days.
7. When several engines need parts, the optimizer allocates shared stock jointly.
8. The authorised planner approves or overrides (an override needs a note). Approved reservations update stock,
   and every decision goes to the decision log.

## Design choices

- **Act on the lower edge, not the point estimate.** Overstating remaining life is the unsafe direction, which the
  NASA scoring function also penalises more heavily.
- **Measure coverage honestly.** The 20 replay engines are never used for fitting, tuning or calibration.
- **Choose the model by a rule written down first.** Among models whose band covers 70–90% on held-out engines,
  the lowest test RMSE wins. The LSTM won (13.6 against 18.4 cycles); see [technical_approach.md](technical_approach.md).
- **Cost stock at replacement value.** Using a spare from stock is not free: it must be replaced. This lets
  reserve, transfer and order options compete on equal terms.
- **Cite emission factors.** Factors per tonne-km come from a government catalogue; air includes radiative forcing.
- **Keep the deployed app light.** The dashboard reads precomputed predictions, so the cloud app does not need
  the model libraries; training runs offline.
- **Keep people in charge.** Every action is a recommendation until a person approves it, and maintenance
  completion is recorded by a person.

## Deployment

Streamlit Community Cloud serves `app/streamlit_app.py` from the public GitHub repository using
`requirements.txt` (Streamlit, pandas, NumPy, Plotly, PuLP with HiGHS, PyYAML). Model training, data
generation, the API and the tests use `requirements-dev.txt`.
